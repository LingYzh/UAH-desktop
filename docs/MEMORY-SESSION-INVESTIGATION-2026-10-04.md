project.rules 的变化来自把工作区外的 UAH 用户/私有记忆路径及 `__uah_scope__` 送入项目规则扫描后产生的 `Ignored target ... outside the granted project root` 警告。这些属于来源诊断，不是新项目规则，却被放进较早的指令区，缩短了可复用前缀。

具体例子：请求 seq=8379→8400 的记忆和项目规则不变，Git 仅 capturedAt 从 `17:37:12.292Z` 变为 `17:37:18.175Z`。最后一请求输入 139,636 token，缓存命中仅 4,352（3.12%）。历史不断增长，而能匹配的头部仅保持较短的一段。

结论：确认存在 **UAH 上下文装配结构的缓存缺陷**。每次重新读取状态是必要的，但把诊断时间、运行计数与动态记忆重新写入位于完整历史之前的 instructions，会截断后面历史的前缀复用。记忆更新有影响，但不是本记录中最先破坏前缀的因素。刚取消的累计 token 停止机制不等于移除了头部中的 token 统计和耗时，因此不会自动修复此缺陷。

[DeepSeek 缓存文档](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)说明缓存依赖完整匹配已落盘的前缀单元，并且缓存是尽力而为。请求侧差异与本次命中分布一致；本次没有对服务端做 A/B 调用，不能承诺修复后的具体命中率，也不能把字符串字符数当作服务端 token 边界。
