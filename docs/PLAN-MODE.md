# Plan 模式与计划文件

会话权限菜单中的 Plan 用于调研与制定实施计划。模型可以读取工作区、搜索和委派只读子任务，不能编辑项目或执行命令。主代理也可以通过 `enter_plan_mode({})` 切入 Plan；Readonly 和子代理不能通过该工具提升权限或改变主会话。

## 写入、展示、提交

1. 主代理阅读现有代码，确认范围、相关路径、方案与验证方法。需要澄清时正常向用户提问，文字回复不会自动被当成已提交计划。
2. `write_plan({content,title?,newPlan?})` 将完整 Markdown 草稿写入应用数据目录的 `plans/<sessionId>/<documentId>/draft.md`。默认沿用当前任务；`newPlan:true` 开始另一项任务，`title` 设置标题，省略则沿用。路径由应用生成，不接受模型自选路径。这里是专用计划文件能力，不开放项目写权限。
3. `read_plan({})` 读取当前任务的真实文件；Plan 优先读取本轮草稿，退出 Plan 后主代理仍可只读引用最新计划。子代理没有计划文件工具。
4. `submit_plan({})` 读取草稿，保存不可覆盖的 `<planId>.md` 版本快照及 SHA-256。也支持 `submit_plan({plan})` 先保存再提交。提交后本轮结束，不执行同批后续工具。
5. 正文在右侧工作面板「计划」页展示，写入草稿或提交新版时自动打开。支持 Markdown、任务与版本选择、复制及文件信息；历史版本只读。对话正文仅保留查看入口，批准／修订自动生成的完整任务输入在界面中缩为决定摘要，模型历史仍保留原文。
6. 待审批时，底部普通输入框替换为审批操作区。查看与复制不会批准；审阅内容来自固定快照，不用外部文件的后续变动悄悄替换。

只有真实调用计划工具才会生成计划文件。工具能力被显式禁用的模型仍可进行文字分析，但不会被包装成完成了文件写入或计划提交。

## 审批与实施

底部提供「批准并自动编辑」（Accept edits）和「批准并逐项审批」（Manual）；展开「其他实施权限」可明确选择 Auto 或 Bypass permissions。只有点击批准才会开始实施，选择权限本身不触发批准。审批后恢复普通输入框，并创建独立实施轮次，使用当前模型和会话思考强度、锁定的主 Agent；旧规划轮次保留审计记录。没有清空上下文或在原工具循环原地恢复。

选择 Manual 时，批准计划之后的每次文件编辑仍需逐次批准；批准计划不是允许模型随意提升权限。当前 Auto 的未隔离命令也仍需审批。

「指导 Agent 修订」（Revise）在底部操作区展开意见输入框。提交非空反馈后恢复普通输入框，在 Plan 模式创建新的规划轮；模型收到当前正文、标题、版本和反馈，沿用同一任务、稳定草稿路径和递增版本。新版仍需再次提交和批准。

「直接编辑 Markdown」在右栏打开标题、Markdown 编辑和预览。保存新版本不调用模型、不批准；旧正文、标题、哈希和快照仍保留。编辑尚未结束时禁用审批和提交修订意见，避免误批准编辑前版本。

审批会复查版本快照与当前草稿内容和哈希。文件被外部修改、删除或替换为不安全链接时拒绝审批。当前任务由会话 activePlanRunId 标识，普通澄清轮不会让计划失效；删除当前计划不会复活旧计划，新任务也不会重新启用旧审批。计划状态、新轮次、会话权限在同一数据库事务中提交，异步校验之后重新检查历史和设置；启动失败不消费原计划，重复请求不能触发第二次实施。

旧版 `plans/<sessionId>/<runId>.md` 仍能读取。首次编辑或修订沿用旧计划 ID 作为任务身份，保留原文件和历史。每条计划记录的手工历史最多100项／200万正文字符，版本号上限10000；超限明确报错。

## 进入与离开 Plan 的提示词

Plan 保持会话权限模式，每次请求都从真实权限重新生成工具目录与持久权限说明。进入、再次进入、手工离开和批准实施分别记录模式转换事件，`plan.transition` 在该事件后的首次模型请求注入一次。

批准离开会标明批准的计划 ID／版本、实施权限与继续遵守工具审批；手工切走则明确「未批准计划，不得自动实施」。切换菜单不会伪造审批。退出后 `plan.reference` 允许引用计划；Plan 工作流模块移除。转换提示不回写用户 Agent 指令、不重复注入每一轮工具请求，子代理不继承主代理转换事件。

## 与普通对话操作的关系

- 创建分支立即保存新会话并展示截止该回复的历史文本，继承主 Agent 快照、当前模型与会话控制设置。原会话和分支的后续修改相互独立。
- 编辑回复仅改变显示正文，不修改计划文件、提交快照或审批记录。
- 发生过项目文件改动的整个会话隐藏重新生成；子代理、重试、先改后恢复和已执行但无法确认文件副作用的命令也纳入限制。运行时再次校验，不能通过直接调用 IPC 绕过。
- 专用计划草稿不作为项目文件修改统计。项目改动继续通过工具快照与轮末改动清单展示。

## 参考与适配

本轮核对了用户更正后的完整参考仓库中的 [EnterPlanModeTool](https://github.com/noya21th/claude-source-leaked/blob/main/src/tools/EnterPlanModeTool/EnterPlanModeTool.ts)、[ExitPlanModeV2Tool](https://github.com/noya21th/claude-source-leaked/blob/main/src/tools/ExitPlanModeTool/ExitPlanModeV2Tool.ts)、[退出计划工具说明](https://github.com/noya21th/claude-source-leaked/blob/main/src/tools/ExitPlanModeTool/prompt.ts)、[计划文件管理](https://github.com/noya21th/claude-source-leaked/blob/main/src/utils/plans.ts) 和 [Plan 子代理](https://github.com/noya21th/claude-source-leaked/blob/main/src/tools/AgentTool/built-in/planAgent.ts)。采用的行为是专用计划文件、只读调研、提交后由用户审阅，以及主代理和规划子代理的权限分离。

UAH 按自身 Electron/数据库/多协议工具运行时独立实现：工具命名为 enter_plan_mode/write_plan/read_plan/submit_plan，文件按任务及版本保存；没有移植参考项目的终端框架、遥测、订阅判断或隐藏功能开关。Plan 不是额外进程沙盒，现有文件与命令权限检查继续生效。
