# 原生 Codex 权限与内建指令

2026-10-03。本页说明当前实现，取代早期 D09 的只读 MCP 拦截和权限菜单 Plan 说明。

## 原生权限

| 界面预设 | 原生沙箱 | 原生审批策略 |
| --- | --- | --- |
| 只读 | read-only | never |
| 默认权限 | workspace-write | on-request |
| 完全访问 | danger-full-access | never |

只读模式允许原生只读命令。MCP 保持原生配置中的启用状态；文件沙箱不保证外部 MCP 没有副作用。完全访问使用原生无沙箱配置。UAH API 模式仍使用自己的权限体系，二者不混用。已有 auto/accept-edits 原生会话归入默认权限；旧 plan 转为独立计划模式。

## 指令

- `/plan` 切换原生计划模式；`/plan on`、`/plan off` 显式切换；`/plan 任务内容` 开启计划并执行该任务。计划模式与文件权限独立，使用 Codex 内置计划指令。模型发出的提问显示为可填写的卡片，提交后原生轮次继续；原生子代理的问题也在父会话显示。
- `/goal 目标内容` 设置原生目标并开始执行。`/goal --budget 5000 目标内容` 显式设置 token 预算；不写预算时不会自动猜测。
- `/goal` 查询；`/goal pause` 暂停；`/goal resume` 恢复；`/goal clear` 清除。查询、暂停、清除只调用目标接口，不发送模型轮次。
- 目标仍为 active 时宿主继续原生轮次，直到原生报告终态、用户停止或宿主预算/超时中断。每个可见轮次计入宿主预算，用量累计。原生内部请求和中途消耗仍不可精确观察。
- 用户点击停止后，宿主确认中断并查询目标，仅将仍 active 的目标设为 paused；已经完成的目标不改写。暂停未获确认时明确要求核对，不假报暂停。确认停止且配置未变可用 `/goal resume` 恢复同一原生线程。超时、预算耗尽和异常不会冒充用户暂停请求。

模型菜单展示 model/list 返回的名称，实际请求及持久化继续使用模型 ID。配置改变或历史编辑需要新线程时，不会把旧线程的目标状态伪装成新线程目标。

## 表单与错误提示

Provider 的协议、地址、模型及 API Key 可独立修改；留空的保留操作继续使用已加密保存的 key，显式替换或清除才改变 key。MCP 连接器的凭据变更规则独立于 Provider 表单。

当前客户端语言为简体中文。IPC、表单、运行和子任务的错误展示统一经过客户端错误格式化；常见网络、认证、路径和超时错误提供中文说明，未知外部错误提供中文提示。日志中的原始诊断、模型文本、工具输出不当作界面文案翻译。

原生 JSON-RPC 拒绝响应保留请求方法、错误码及服务端 `error.message`，同时提供中文说明；运行失败提示与会话导出均可排查。原始诊断最多 8,000 字符，超长明确省略；URL 凭据、Bearer、常见认证字段及宿主已登记的连接器秘密脱敏。任意 `error.data` 不直接透传，避免暴露请求正文。旧记录中已经丢失的具体原因不能补回，需要更新构建后重新复现。

## 对话内容、附件与计划迭代（2026-10-03）

输入框左侧 `+` 菜单集中提供附件、Plan、Revise 和 Goal 指令入口。菜单填入指令供用户编辑并发送，不直接发起模型请求。计划面板的「执行计划」按钮则明确发起实施。

- 原生 commandExecution、mcpToolCall、dynamicToolCall、fileChange 显示实际参数、输出、退出码或错误。流式输出有长度上限和截断提示；原生文件操作不伪造 UAH 文件快照。思考区只显示 Codex 公开的 summary，兼容历史 JSON 记录，不显示私有 reasoning content。
- 原生计划正文和 `turn/plan/updated` 步骤同步进入 UAH 计划面板。`/plan revise 修改意见` 保持 Plan；`/plan execute` 切回 default 后执行已确认计划。在 Plan 模式下，独立输入「执行计划」等明确短句也会退出 Plan；包含否定、引用或问题的普通文本不会误触发。修订按钮填入 `/plan revise `，等待用户补充反馈。
- 原生工具说明要求多步骤任务使用原生计划工具；启用 UAH 委派工具时，适合拆分的独立任务优先使用 UAH 子代理，先读取真实预设，不猜测 provider ID。简单任务不强制委派；保留角色、模型、预算和用户选择。
- 附件本轮只支持原生 Codex。支持系统文件选择、多文件拖入和图片粘贴。图片作为 `localImage` 发送；文本/代码发送受限大小的内容快照；PDF、Office 等其他文件仅提供明确本地路径，由模型用实际工具和当前权限读取，不宣称已经解析。
- 每条最多 8 个附件；图片每个 5 MiB、合计 10 MiB；文本每个 256 KiB、合计 512 KiB。无法可靠解码的文本拒绝导入，不静默截断。待发送附件有过期时间；图片/文本发送后保存在会话工件中，记录只包含引用，随会话清理。同一原生线程可继续使用其历史附件；新建线程的历史文本恢复不承诺重放旧附件二进制。

## 工具详情与原生线程关联

UAH 桥接工具与 Codex 的动态工具事件采用统一展示：显示用途、实际工具名、参数和结果摘要，摘要之外的原始返回可单独展开。同一轮里，只有调用 ID 和工具名都一致、且宿主调用已结束时，才合并桥接/原生重复显示；日志原始证据不删除。未知工具保留真实名称和可用原始参数/结果，不再因未加入名称字典而隐藏已有详情。

一个 UAH 会话可能关联多个原生 thread。兼容的完成/停止轮次继续原线程；恢复失败、历史修订、重试、运行时设置或工具/扩展配置变化等可能需要新线程。已有原生线程的主会话在新建前显示原因和旧线程 ID，用户必须点击「新建线程并继续」；取消或中止不会创建线程。首次对话与本来就独立的子代理线程不需要此迁移确认。需要核对的异常仍先完成核对，旧目标也不能借新建线程冒充续接。

原生工具只在 thread/start 注册，因此工具契约变化不能靠继续旧线程虚构已更新的能力。日志 `uah/thread-selection` 明确记录 start/resume、前一线程和原因码，`uah/thread-replacement-decision` 记录迁移确认结果。确认等待期间配置或历史发生变化时不沿用过期确认，需要重新发送核对。恢复失败不会自动重试到一个未经确认的新线程。旧日志没有记录的指纹差异不能事后猜测；指定历史会话的调查见 [NATIVE-SESSION-INVESTIGATION-2026-10-03.md](NATIVE-SESSION-INVESTIGATION-2026-10-03.md)。

对话的折叠内容首次展开时才挂载，展开后保留以维持关闭动画和内容状态。用户操作思考/工具折叠区时暂停自动滚动，避免展开动画的尺寸变化反复触发滚动到底；用户滚动回底部可恢复跟随。

## 真实上下文计数来源

直接接入 Codex app-server 的 `thread/tokenUsage/updated`，严格匹配线程和轮次。最近请求的 `last` 与线程累计的 `total` 分开存储和显示；缺失字段显示「未上报」，不填零。详情包含输入、输出、缓存读取/写入、推理输出和模型上下文容量。

上下文计数使用 `last.totalTokens`，容量使用 `modelContextWindow`，界面百分比是两者原始比值，不把累计消耗当成当前上下文。核对本机 CLI 0.156.1 对应源码后确认 `tokens_in_context_window()` 使用 total_tokens；CLI 的剩余百分比还扣除 12,000 token 基线，因此不能声称 UAH 原始比例与 CLI 的取整百分比完全相同。系统提示词、历史、工具各自占比未通过此通知暴露，不虚构分类明细；通知也不是下一次请求的预测。

来源：[官方 app-server 文档](https://learn.chatgpt.com/docs/app-server)、[对应版本协议源码](https://github.com/openai/codex/blob/rust-v0.156.1/codex-rs/protocol/src/protocol.rs)。本机 Luna 实测最近 total 19,907、input 19,900、output 7、cached input 16,128、reasoning output 0、window 258,400；这是一次验证样本，不是模型固定额度。脱敏证据在 `artifacts/native-context-live.json`。
