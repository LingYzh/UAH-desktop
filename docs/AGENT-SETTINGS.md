# Agent、模型与权限

## 配置归属

主 Agent 只保存名称、用途、指令、启用状态和继续委派开关，不接受模型或生成参数字段。继续委派默认开启。模型选择独立于 Agent；切换 Agent 不修改当前模型。

「模型与账号 → 编辑端点 → 模型生成设置」保存该 provider + model 的 temperature、top P、输出预算、历史轮数、请求超时和停止序列。所有字段有用途说明。相同模型 ID 在不同 provider 下配置独立；刷新目录和卡片启停保留生成设置，移除模型时移除对应设置。

可选数值留空使用协议/服务默认值；历史轮数默认 50，0 表示仅发送当前消息和 Agent 指令；超时默认 60 秒。只发送已完成问答对。默认思考强度不发送该参数，none 是明确关闭思考，二者不同。

Responses 不支持停止序列；OpenAI 协议不接受 Anthropic 思考预算。思考参数的协议与档位必须受所选服务支持。无效组合明确报错，不静默重试。连接测试仍使用独立的 256 token 短输出请求，仅验证连通性；正式对话使用已保存的模型参数。

## 会话锁定

第一次成功落库的运行锁定主 Agent 的身份、名称、指令及委派标志；即使这一轮之后生成失败，锁定仍保留。开始前的配置解析失败不会锁定。UI 禁止变更，运行时也拒绝伪造的更换请求。

后续编辑、停用或删除角色不会改变已有会话的锁定快照；新会话使用最新配置。API 会话仍可换 provider/模型，每轮读取所选模型参数并用会话思考强度覆盖，写入独立 modelParameters 快照。不能通过 API/本地验证切换绕过锁定；需要新建会话。旧轮次 agentParameters 仅保留历史数据，新轮次不再使用。

## 权限

| 模式 | 配置含义 |
| --- | --- |
| manual | 默认模式；读取工作区，修改和执行命令需审批 |
| plan | 只分析和规划；禁止修改和命令，发送 Plan 系统约束 |
| readonly | 仅允许读取授权工作区内内容，禁止编辑及命令 |
| accept-edits | 自动允许工作区内编辑；命令执行需要审批 |
| auto | 授权工作区内自动执行工具 |
| bypass | 允许任意操作，不限制工作区范围或逐次审批 |

权限仅属于会话，不在主 Agent 或子代理预设中配置。全新使用须手动选择模式；后续新会话继承上次创建快照。可在无运行时变更，立即保存并在下一轮生效；不会更改历史运行。子代理可继承或指定具体模式，操作范围和审批要求均不能超过父运行与当前会话的共同上限。临时 Agent 指令不能提权，工作区从父代理传递。Plan 与 readonly 权限范围相同，Plan 额外要求先规划。

已接入文件读取/搜索/编辑与命令执行，工具派发实际校验权限、路径和审批。本地工具要求明确工作目录；无目录仍可进行模型对话和子代理文本任务。任意 PowerShell 命令无法仅靠 cwd 隔离，manual/accept-edits/auto 均需要逐次审批，只有 bypass 自动执行；审批显示命令与目录并明确此边界。只终止直接创建的命令进程，无法保证其后代进程随之退出。文件操作拒绝路径越界、符号链接/重解析路径、危险 Windows 名称；覆盖必须匹配先前读取的完整内容。以上不是操作系统沙盒，无法抵御恶意并发替换文件系统命名空间。本地验证保留原来的显式审批流程。

## 子代理启动配置契约

子代理角色保留名称、用途、指令、启用和可选绑定模型，不再包含生成参数。全局只保留启用、并发、深度、历史继承和任务超时。调用时总能指定 provider、模型、思考强度和 Agent 来源，不再提供限制这些选择的开关。

`previewDelegation({ parentRunId, request })` 经可信 IPC 进入 utility process，由父运行快照与当前会话共同限定权限，并由父运行快照取得角色，而非信任调用方提供的父权限。返回配置计划，`executionAvailable: false`；不启动任务、不占并发名额、不调用模型。

parentRunId 是宿主信封字段，用于桌面配置校验。后续接入模型工具时必须由宿主绑定当前真实父运行，不能把它作为允许模型自由选择的工具参数；模型只能决定 request 内容，不能借其他会话的运行 ID 取得更高权限。

```json
{
    "parentRunId": "persisted-run-id",
    "request": {
        "providerId": "endpoint-id",
        "modelId": "model-id",
        "reasoningEffort": "high",
        "agent": { "type": "inline", "name": "审阅助手", "instructions": "检查变更风险。" },
        "permissionMode": "readonly",
        "context": { "mode": "none" }
    }
}
```

Agent 来源还支持 `{ "type": "inherit" }` 和 `{ "type": "preset", "id": "child-profile-id" }`。继承 Agent 不等于继承聊天历史，历史由独立设置控制。显式 provider 必须配模型；省略选择时优先使用子代理绑定，再继承父模型。未指定思考强度时继承父代理会话的强度。端点必须可用、模型必须属于该端点；拒绝不存在、停用、跨 provider 猜测及权限提升。

每次调用的 context 由主代理自行决定，始终可以覆盖全局历史默认值：

- `{ "mode": "all" }`：继承父代理本次运行实际可见的完整文本上下文窗口，包含该父轮输入和截至校验时已有的输出。遵守父模型当轮历史窗口，排除后来的轮次及其他会话；不会静默扩大父模型本身没见过的历史。
- `{ "mode": "selected", "messages": [{ "role": "user", "content": "主代理挑选的片段或整理后的摘要" }] }`：只提供主代理选择的内容，允许 user / assistant 消息；不补入其他父历史。
- `{ "mode": "none" }`：无父对话历史，作为新会话处理；仍有选定 Agent 的指令、子任务和父权限上限。

省略 context 才使用全局 inheritHistory 的默认值。返回 contextMode 和复制后的 contextMessages；Agent 来源、模型和权限独立。上下文最多 1000 条、序列化 UTF-8 总大小 1 MB，超限明确要求选择部分或提供摘要，不悄悄截断。系统指令不能混入 selected 消息；应通过 Agent 选择/临时指令配置，也不能借此提权。当前上下文仅文本，后续工具/附件执行接入时需扩充实际消息快照。

全局关闭、父代理关闭委派、超过最大深度均拒绝。根为第 0 层。并发与任务超时已在调度器执行，子代理有真实 parentRunId/depth；停止父任务会递归停止其子任务。模型通过 spawn_agent 立即取得 ID，通过 wait_agents 等待结果，通过 list_agent_presets 读取可选角色。父模型只可等待自己的直接子代理。

## 存储与迁移

Agent 配置存于 utility process 管理的 agents.sqlite v3，端点与模型生成设置存于 endpoints.sqlite v4。两侧均保持严格字段校验、大小上限和 revision 冲突保护。损坏配置不静默重置。

旧 Agent v1 在事务中迁移，原始完整 JSON 保留在 agents.sqlite 的 agent_settings_legacy 表。主 Agent 的原模型绑定与生成参数不再生效；由于参数以前可能未绑定模型、多个 Agent 也可能冲突，不擅自分配给全局模型，请在模型生成设置中重新确认。旧子代理模型绑定保留。原 read-only 映射 readonly，workspace-write 映射 accept-edits，主 Agent inherit 映射 readonly。按本轮默认要求开启旧主 Agent 的委派标志，但全局子代理开关保持原值。

配置结构参考过 Codex 的角色配置思路，UAH 不导入 Codex 凭据或宣称 TOML 全量兼容。

## 会话思考强度

会话中的思考强度选择器在下一轮请求生效，保存并支持重启恢复。运行中禁止变更。模型页移除思考强度与固定预算控件；旧字段仅为存储兼容保留，不再影响请求。服务默认不发送强度/预算；none 显式关闭；其他档位原值发送，不静默降级。

- Chat Completions：reasoning_effort，展示服务返回 reasoning_content/reasoning。
- Responses：reasoning.effort；明确开启思考或声明支持时请求 summary:auto，展示服务返回的 reasoning summary，并在工具循环内保留加密 reasoning 项。见 [OpenAI reasoning](https://developers.openai.com/api/docs/guides/reasoning)。
- Anthropic：none 发送 thinking.type=disabled；low/medium/high/xhigh/max 发送 adaptive 和 output_config.effort，minimal/ultra 拒绝。展示 thinking 文本，工具后续请求保留 signature/redacted thinking。见 [Anthropic effort](https://platform.claude.com/docs/en/build-with-claude/effort)。

仅展示接口实际提供的思考或摘要，不补造未返回的内容。所有思考与工具活动支持折叠，工具审批动作在滚动区外。

## 新会话快照

首次使用手动选择主 Agent、provider/模型、权限、思考强度以及目录（可明确无目录），未完成不能发送。本地验证只要求明确运行方式和目录选择。首次发送保存 initialConfig；新会话从最近创建会话的 initialConfig 复制，与正在浏览哪个会话无关。之后在旧会话修改模型/权限/强度不改变新会话模板。无有效快照时留空；已删除 Agent/端点不自动替换成其他值。现有旧会话仍能继续使用。

## 工具与子代理运行

单轮最多 16 次模型/工具循环，仅在完整流正常结束后执行工具调用；参数、标识、输出和上下文受大小上限约束。工具结果按原调用 ID 回传，保持三协议原生历史；服务错误与截断不执行半截调用。文件操作仅 UTF-8 文本，单文件上限 1 MiB，命令输出上限 64 KiB；暂不支持交互终端。编辑保存文件前后快照，写入已发生但快照保存失败时明确报告而不自动重试。

子代理实际运行与 UI 展示已接入。可继承/预设/临时 Agent，自选 provider/model/effort/context，不能越过父权限；未指定 effort 继承父会话强度。全量上下文是父当轮实际文本窗口及当前工具活动的文本表示，不包含其他会话或后来的轮次、其他子代理的独立对话；同一模型工具循环需要的 opaque reasoning 留在原生协议历史中。子代理结果通过等待工具返回主代理。

重启不自动重放运行或工具，未结束父子任务标为 stopped、审批过期；已经发生的文件改动保留。MCP、电脑操作、附件和官方 CLI/订阅仍未接入。

v2 → v3 在事务中移除角色权限，完整旧文档保留于 `agent_settings_legacy_v2`；v1 原始归档继续保留。旧会话无 controls 时保留有效 requested 权限，无效时回退 manual；不从已修改的角色模板读取权限。`set-session-controls` 使用 revision 防止旧页面覆盖新设置。

## 子代理侧栏与停止理由

右侧工作面板新增子代理页。首级列出当前会话全部子代理（含下级及历史轮次），点击名称进入第二级只读任务、思考、工具和回复视图；没有消息输入、模型/权限修改或审批按钮。主时间线只保留状态和查看入口。列表可停止正在运行或等待审批的子代理，弹窗理由可留空，最多 2,000 字符；关闭弹窗不停止。理由与运行记录一起保存，wait_agents 返回给父代理，停止同时结束其下级任务并使待审批操作过期。

并发文件编辑使用每个规范路径的写入锁，在锁内再次检查 expectedContent；同文件的子代理修改不会互相静默覆盖，取消排队编辑不会落盘。

## 默认助手与编排工具可用性（2026-09-27）

新安装默认启用子代理，并为默认助手提供可编辑的协作、工具、权限与编排提示词。schema v4 将原 v3 文档归档到 agent_settings_legacy_v3，仅补充内置 default 主 Agent 的空提示词；不覆盖非空自定义指令或用户创建的角色。仅未保存修改的旧默认配置自动开启子代理，已保存的关闭选择保留。已有会话锁定的指令快照保持不变，新提示词用于新会话。

每次 API 请求附带运行时编排说明：说明实际工具是否可用及原因（模型明确不支持工具、全局关闭、当前 Agent 不允许委派、深度上限）。可用时发送 list_agent_presets、spawn_agent、wait_agents；达到深度上限不再发送下级编排工具，服务端仍验证权限与边界。Agent 设置页直接显示编排开关状态，避免只有角色配置却不知道工具被总开关隐藏。

## 并行启动、有界等待与工具说明

spawn_agent 创建后台子任务后立即返回，主代理可继续自己的工具/模型循环，多个子代理并行运行。wait_agents 是主动同步点：只暂停调用方，后台任务继续执行；新增 timeoutMs=0 即时查询，省略默认最多等待30000毫秒，允许0–60000毫秒，全部指定子代理结束时提前返回。超时不取消任务，返回各任务当前状态及可能尚未完整的输出。主代理仅在依赖结果或没有其他可推进工作时等待；运行时指令明确禁止每启动一个就立即等待及反复零超时忙轮询。父轮最终结束前仍会收拢自己的子任务，避免遗留任务继续修改工作区。

8 个已开放工具均补充了模型可见的详细描述、各参数含义/默认值/上限、有效示例、结果格式、错误和重试规则。说明直接放在 tools 定义中，三种协议均复用；不依赖模型猜测或默认 Agent 提示词。完整导出参考见 [TOOLS.md](TOOLS.md)。
