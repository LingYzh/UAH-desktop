# 只读 Git 与请求上下文

## 2026-09-28 实施规格与组件盘点

用户明确本轮只接只读 Git：分支、变更状态、diff、近期提交及请求前上下文。不提供暂存、提交、切分支、worktree 或远端网络操作。

组件盘点：目录入口复用现有 location-chip；Git 内容复用 UiTabs/UiButton/UiCard/UiCodeBlock/UiSelect；请求详情复用 UiDialog/UiCollapse/UiCodeBlock。唯一通用缺口是原型的上下文用量环、分类条与未知状态，先在 D:/UI 新增 UiUsageMeter、导出 API、真实 demo 和文档。

root 已检查 D:/UI/artifacts/usage-meter-qKhMlm 的六张浅深主题、1440/900 宽和 125% 缩放截图：字重、图例、颜色、间距、未知/估算/超限状态符合原型，组件无横向溢出；结合键盘与动态状态回归通过视觉验收。详见 D:/UI/USAGE_METER_VALIDATION.md。之后才进行 UAH 组装，不新增业务样式。

Git 从已授权的会话目录或选择器目录读取；目录、路径、操作在宿主再次校验。使用有限的 Git 参数接口，不向渲染进程提供 shell。嵌套目录只暴露其下的文件变更，diff 禁用外部 diff 和 textconv，每次模型请求重新取状态。不存在仓库、Git 不可用或读取失败时明确显示状态，不伪装成干净仓库。工具按真实注册结果启用条件提示词，Plan/Readonly 可读取 Git。

上下文展示最近一次请求的本地可见投影，不是下一次请求预测，也不是精确 token 账单。服务 input usage（包括缓存输入）用于已知输入用量；未上报时以可见文字粗估并标记。容量来自已配置模型元数据，缺失保持未知。分类始终独立估算，不强行凑成服务计数。私有推理、加密字段、连接密钥和授权头不会进入详情。

每轮保存最后一次请求的有界详情，详情单独存储、按需读取，不反复随输出 delta 传输。删除或编辑历史后，受影响会话的旧详情失效，避免通过上下文查看器恢复已删除资料。动态 Git 与环境不会写回 Agent 配置或历史指令快照。

本轮不实现自动压缩、长期记忆、MCP、CLI 原生运行时或任意 Git 写操作。

## 实现边界

- API 每次请求前采集 Git 状态；分支、HEAD、上游本地计数、至多200个变更文件可供界面查看，提示词另做5500字符以内的编码预算与截断说明。当前目录之外的文件不会出现在列表或 diff 中；子模块内部状态不读取。
- `git_status` / `git_diff` / `git_log` 使用有限参数契约，执行前再次核对工具注册表。目录必须由系统选择器授权或来自已有会话。每个 Git 子进程最多5秒、2MB输出；diff最多64000字符，log最多20条。禁用可执行 diff、textconv、过滤器、签名验证、子模块遍历和自动获取对象；partial clone 明确返回不可用。只读命令不触发暂存、提交或分支写入。
- Git 配置键逐次读取并覆盖过滤器，不提供抵抗恶意并发替换 `.git` 配置的原子沙箱。这与当前普通本地文件工具的目录信任边界一致。
- 最近请求详情每个轮次最多240000字符、单分类100000字符，超出有截断说明；估算按完整可见投影计算。最多500轮的现有历史上限继续适用。详情在 runtime.sqlite 的独立 request_contexts 表保存；schema v1→v2事务迁移保留旧历史。普通run事件只传摘要。
- 详情包含实际指令分组、原生历史的公开消息/函数调用/工具结果和工具schema，隐藏reasoning/signature/encrypted内容只记录“已省略”标志。端点凭据从不传入捕获函数。它不是可用于协议重放的完整原始请求。
- 服务 input/output/cache usage 按单次请求快照替换、不累加；新请求清空上一请求计数。Anthropic input包含已报告缓存读取/创建，OpenAI缓存是input子集。未报告total不派生；上下文环使用input，不用input+output。分类是本地启发式估算，与服务账单独立。上下文容量只来自当次模型元数据，缺失保持未知。
- 编辑/删除回复或编辑计划，与对应历史提交同一事务删除本会话旧详情；随后清掉显示摘要。重启不能通过查看器恢复被删除的旧详情。分支已有独立历史仍遵循原有分支语义。

## 运行时修复

1. 失败/停止轮次保留原任务与有界宿主中断记录；已写文件以持久化快照为凭据，命令等无法验证的副作用明确标为不确定，后续模型不能盲目重放。中断分支在创建时把宿主摘要与原任务绑定，不把用户仿造的标记当作新角色。
2. 主代理普通结束前等待直属子任务；未被后续模型请求消费的终态结果作为宿主资料送回模型确认。已经通过wait消费的结果不重复，取消及时传播，仍保留16次模型循环上限和Plan提交审批语义。
3. Chat Agent流必须有明确的`finish_reason: stop`才能完成无工具响应；仅有`[DONE]`视为不完整。三协议均解析有效的服务usage，缺失或非法数字不补零。
