# D08 显式核对与续接

2026-10-04 更新：累计估算及服务商报告的 token 仅作统计，不再阻止执行。续接不再追加或展示 token 额度；旧数字上限和已超限快照仍可读取，恢复时归一为无 token 上限，保留历史计数。旧停止记录不被改写，不自动重放请求或工具。其余核对和运行限制保持下述机制。

2026-10-02：失败或停止的最新 API 根任务支持“核对并继续”。旧运行保留，新运行通过 resumeOfRunId 关联；重启不自动发送请求，不自动重放旧工具。Plan、子任务、非最新任务、活动任务和记录失败任务不能使用此入口。

TaskTreeBudget.restore 严格校验持久快照，保留累计请求、工具、token 和已用时间。旧在途请求已经计费的额度不退回；恢复后释放旧并发占位，停机时间不计入执行时间。用户明确继续时追加一个标准任务预算，累计计数不清零。新运行创建、关联事件和状态通过同一事务提交，记录失败不会启动 HTTP 请求。

核对读取持久工具结果及文件版本，在应用内读租约下检查批准目录中的普通文件。拒绝链接、硬链接、目录穿越和身份变化；区分原始字节与 UTF-8 文本 hash，并检测读取期间变化。缺失、变化、无法核对的文件和未知 dispatch 要求用户记录核对结论。这个结论仅表示用户完成核对，不改写旧工具结果，也不证明用户目标已经完成。外部系统和外部进程仍需实际检查；应用租约不是操作系统沙箱或对外部程序的文件锁。

确认指纹覆盖当前运行、会话修订、日志水位、文件证据、工具定义、Agent 设置和端点公开配置。端点 revision、URL、协议、模型详情或参数变化后旧确认失效，不包含认证密钥。实际建立续接请求前再次核对。新上下文明确携带原任务、补充要求、历史工具证据和人工核对结论，即使 historyTurns 为 0 也不会丢失这些依据；证据作为数据传递，不授予新权限。恢复上下文上限 1 MiB，核对最多 100000 个事件、10000 项资源，超过范围明确拒绝而不是静默丢弃。

canonical recovery.reviewed 保存 reviewId、throughSeq、runIds 和不可变证据引用；未配对 dispatch 只在对应运行及该水位以内解除恢复阻断，后续 dispatch 不受旧确认影响。recovery.resumed 保存源运行及证据引用。离线回放和完整/分享导出保留这些事实与引用闭包；未收到真实结果的工具仍不补造成功结果。
