# PC 原型：新草稿与 Windows 目录权限（2026-09-25）

- PC 原型位于 `D:\UAH\design\UAH_PC_Prototype_v1`；权威功能设计为仓库 `design/UAH_PC_HARNESS_FUNCTIONAL_DESIGN.md`。原型是静态 HTML 交互样本，未连接 Windows 沙盒或官方运行时。
- 用户取消独立“会话默认值”设置页。普通新草稿会记住 Agent、模型、思考、权限与项目；首次没有已记住模型时保持未选择、禁用发送。历史会话与分支的选择不写回新草稿选择；正文、附件和 worktree 方案不继承。
- 附加目录只作用于当前会话，入口已合并到输入区上方的主目录选择菜单；只要先选主目录即可添加，不要求先选模型。随首次发送保存到该会话，新草稿和分支不继承。设置页“项目目录”只管理项目列表和根目录。
- 主目录、附加目录以及 MCP 本机工作目录统一走文件夹选择器，不再手填目录路径。网页原型通过 `showDirectoryPicker` 演示，只能可靠获得文件夹名称；真实 Windows 客户端须用系统文件夹对话框取得并校验绝对路径，不能把原型名称用于真实文件操作。
- 新对话页已改为欢迎内容上置、输入区底部停靠，草稿与已开始会话使用同一 `composer-dock` 结构与尺寸；首次发送时输入区不再由页面中央跳到底部。顶部内容在空间不足时独立滚动。
- Windows 目录设计区分工作目录、附加读目录、附加写目录与 Shell 隔离。Codex 取官方运行时实际的 Windows 沙盒状态；Claude Code 原生 Windows 的目录授权及审批不等同 OS Shell 沙盒；UAH 自有引擎需真实 Windows 隔离才能宣称命令已隔离。无目录会话可聊天，项目文件工具和 Shell 在绑定目录前不可用。
- 原型设计说明与产品文案的分类及正式实现清理要求写入原型 `COPY_GUIDE.md`，`CODEX_HANDOFF.md` 明确先读；带 `data-copy-scope="prototype"` 的说明块是必须清理的种子，不代表其他模拟文案可直接发布。
- 本轮未改动 Android App 代码。未在相关 `design/` 或 `.Codex/` 目录发现需要同步的 `CLAUDE.md`。
