# Codex 实施交接 · UAH PC v1

## 先读与优先级

本交付是可执行的 UI 合同，不是“照着描述自由设计”的提示词，也不表示 PC 的真实 Harness 已经完成。先打开 `index.html`，再打开 `gallery.html`；不要只读源码或只看总览图。

**文案清理是正式实现的发布门槛。**先读 [COPY_GUIDE.md](COPY_GUIDE.md)：界面中的“原型说明”、演示状态和固定回复仅用于验收，落地时删除或替换为真实状态；用户必须看到的权限范围、审批和错误原因仍需保留。

功能依据依次为本轮用户明确要求、仓库 `design/UAH_PC_HARNESS_FUNCTIONAL_DESIGN.md`、现有 `AGENTS.md`、本交付 `COVERAGE_MATRIX.md` 与 `DESIGN_SPEC.md`。当前 UI 视觉以 `src/styles.css` 和对应场景实拍为准。Android v3 的旧边界不应覆盖 PC 新文档；不得把 Android 实现中的设备配置或权限直接套到 Windows。

读取仓库基线：`master` / `a149f2ef6f0a955cfd5f289601c5e122e533ab56`。实施前先检查仓库更新，不覆盖用户后续提交。功能设计文档已随本轮原型调整；本次没有创建分支或提交代码。技术栈尚未由这份 HTML 决定。

## 交付中的代码如何使用

`index.html` 是内嵌全部依赖的独立文件；`build.py` 把 `src/` 合并生成它。正式实现应拆出组件、领域状态、平台适配和持久层，不要将 `src/app.js` 中的演示全局状态、固定 fixtures、计时器和场景重置器当成生产引擎。

建议组件边界：WindowChrome、ProjectSidebar、SessionHeader、ConversationTimeline、TurnChanges、Composer、InlineToolDisclosure、HistoricalDiff、SessionWorkbench、RuntimePicker、ApprovalSurface、ManagementLayout、PermissionGate。命名只是拆分建议，不要求绑定某一种框架。

关键数据应至少区分 Project / WorkingDirectory / Session / Turn / ToolCall / SavedFileDelta / RuntimeConnection / RuntimeCapabilities / TargetGrant / ScreenLease / ImportPreview。所有渲染必须来自对应数据对象，不能从可见文本反推真实状态。

## 不可退化的交互约束

命令收起只有“运行了命令”，运行 / 审批 / 失败 / 中止显示各自状态。展开 command / output 必须对应同一次调用。文件编辑内联 Diff，无“完成 N 步”外层大卡片，无默认工具弹窗。每轮末尾始终有改动汇总，包括“本轮无文件改动”。

保留独立模型、思考档位、权限、目录和上下文入口。新对话欢迎内容放在上方独立滚动区，草稿与聊天复用同一个底部 composer 停靠尺寸；首次发送不得出现输入区从中央跳到底部。正文不变成聊天气泡网格。用户消息是浅暖灰气泡，助手是阅读正文。正常对话不是仪表盘。

打开历史 Diff 不读取当前文件替代快照。查看计划不等于批准执行。展开工具不是重新运行工具。编辑 / 删除历史不自动重跑或撤销文件。

初始为草稿，首次有效发送才原子保存；保存过程必须防连点。活动 Git 同目录才出现 worktree / 共享选择，普通目录不可使用 worktree，只有已停止历史不弹并发提示。

不实现单独的“会话默认值”设置页。普通新草稿里的 Agent、模型、思考、权限和项目变更立即记住；首次无已记住模型时禁用发送。附加目录从会话输入区的主目录选择菜单进入，只有选了主目录才开放，不要求先选模型；只作用于当前会话，下一段新会话与分支不继承。历史会话和分支不改动下次新草稿默认选择，正文/附件/worktree 方案也不继承。发送快捷键归外观设置。

从原生运行时 A 切换 B 必须新建确认过的分支，不迁移私有缓存、内部任务状态、隐藏推理和待审批操作。配额或能力未报告不是 0，更不是“全部支持”。

导航离开不能取消任务，退出应用则必须中止受管理的任务、记录原因，重启不自动运行。取消贯穿网络、工具、子任务和 UI 控制。原型计时器停止仅作为 UI 样本，不构成这一实现。

MCP / 插件全局安装与项目启用分离；hooks 必须逐项启用并授权。电脑控制总开关默认关闭；还必须叠加 Agent、会话模式、目标授权与屏幕租约。导入旧 Android 数据不能赋予 Windows 授权。

## 正式化时必须补齐

官方运行时用各自支持的管理接口或官方客户端；不将订阅凭据复制为通用 API Key。MCP 和插件格式按实际能力逐项适配，不静默改官方全局配置。所有登录状态、账号、模型和工具支持都来自真实检测。

历史文件改动须结合工具事件、运行前后快照和目录监测；并发 / 外部介入无法归因时标记不确定。子代理和 Shell 改动汇入正确父任务轮次。二进制 / 大文件 / 快照缺失保留原因与元数据。

状态应按 session / turn / toolCall 存储：工具展开、右栏标签与选中文件、浏览器标签、终端缓冲区、滚动位置都需要正确作用域。不能照搬 fixture 的简化 ID 或全局浏览器状态。

安全执行、目录 canonical 校验、敏感凭据安全存储、权限交集、插件安装验证、导入事务与取消不能仅依赖前端按钮禁用。前端验证只改善交互，后端必须再次验证。

Windows 目录授权必须同时显示文件访问和命令隔离的有效状态。附加目录只在当前会话的主目录菜单下配置并保存于该会话，不设全局附加目录值。主目录、附加目录、MCP 本机工作目录都调用 Windows 系统文件夹对话框；取得绝对路径并校验后才能写入配置，不接收手填路径替代选择结果。网页原型 `showDirectoryPicker` 只留下文件夹名称以演示流程，`pathKnown: false` 和 `source: browser-picker` 不能作为真实执行路径。Codex 官方运行时以其原生 Windows 沙盒和回报的可读/可写范围为准；Claude Code 原生 Windows 的附加目录与工具审批不能冒充 Shell 的操作系统沙盒；UAH 自有引擎需要真正的 Windows 命令隔离才能显示“已隔离”。无目录会话可聊天，但项目文件工具和 Shell 暂不可用。路径规范化、联接点、盘符和网络共享的处理不能照搬 Android `allowedDirectories` 字符串列表。

Markdown / 数学 / Mermaid 应使用正式安全渲染方案；不得把本交付的固定样本拼接器作为生产解析器。输入法、辅助技术、键盘可达性、链接策略、异常长行和附件需要原生验证。

## 截图验收办法

先对比新对话与完整三栏 Diff，再验命令展开、计划审批、模型切换、供应商、MCP、插件 hooks、数据导入和电脑控制。每个场景都应同时检查浅色 / 深色和交互终态；不要用某一页对齐代替全应用完成。

标准画布 1440×1000。另验 1366×768、1024×768、800×900 与 1920×1080，窄窗分栏下审批和停止仍要可达。系统字体不同可以导致合理的文字宽度差，但列宽、密度、层级、圆角、色彩、正文和工具结构不应擅自改写。

验证真实滚动、粘性输入、弹层焦点闭环、快捷键、减少动效、侧栏拖动和连续快速操作。不要为像素比较关闭安全提示或删除异常状态。

## 禁止进入正式导航的内容

“原型导览”、62 场景列表、fixture 重置、演示运行时、模拟账号、假连接测试、假文件与虚构动作日志都仅供设计验收。正式版无真实数据时显示空态 / 未配置 / 未连接，而不是继续用样本内容。
