# Review fixes for the desktop prototype

This document maps the UAH-01–09 findings in the desktop UI/UX review to the prototype changes and their regression coverage. The prototype remains fixture-driven: it does not call a model, provider API, shell, filesystem, OAuth flow, or desktop runtime.

| Finding | Prototype correction | Regression coverage |
|---|---|---|
| UAH-01 | Rendering reconciles keyed DOM nodes so editable controls keep identity and focus. Drafts are stored under the form scope rendered in the DOM, isolating Agent/provider/memory/search edits. Dirty navigation offers save, discard, or cancel across new-chat entry points, settings tabs, and session selection. Failed saves roll back and retain the draft. | Existing interactions plus `tests/review_regressions.py`: node identity, Agent A/B isolation, dirty navigation choices, and failed-save retention. |
| UAH-02 | Panel close transitions carry a per-session generation and are cancelled when the panel is reopened or the selected session changes. Completion checks the original animation and generation. Background renders retain the closing animation class. | Existing interactions plus the focused close/reopen race regression. |
| UAH-03 | Imports stage changes across agents, providers, memories, sessions, MCPs, and plugins. Mid-transaction or storage failures restore all six collections and the prior backup; failure is reported without an “import complete” state. A failed undo keeps the current data and recovery snapshot. | Mid-transaction and storage failure injection, successful six-collection import, failed undo and successful undo. |
| UAH-04 | A session export/import envelope preserves visible conversation text, follow-ups, plan history, background-task records, and subagent turns. Imported work is stopped; attachments, extra directories, worktrees, credentials, and execution grants are excluded. Unknown model IDs remain attached to the history. | Existing export safety check plus session round-trip regression. |
| UAH-05 | API models persist a stable `providerId`, independent of provider display names. Provider-only model/capability changes remain in that provider’s draft. Disabled or deleted providers block sending, and unknown model IDs are shown as unavailable without silently selecting a different model. | Existing provider checks plus focused draft isolation, persistence, rename, and unavailable-send regressions. |
| UAH-06 | Chat and panel scroll positions are saved only from the keyed scroller belonging to the active session and panel. Restoration is immediate; panel scroll anchoring cannot shift the restored offset during its width animation. | Long conversation switching, management-page return, and a long saved plan restored to its prior offset. |
| UAH-07 | Toast text lets pointer input pass through to the interface; its close button remains clickable. The expiry timer pauses while the toast is under the pointer or contains focus. | Focused hover, focus, click-through, and close regression. |
| UAH-08 | System and app reduced-motion preferences share the same behavior. They disable animations, including continuous effects, transitions, and smooth scrolling. | Focused system-preference and app-setting regression; existing appearance checks. |
| UAH-09 | Font selection and search service/address settings are stored as non-sensitive preferences. UI feedback distinguishes persisted settings from values retained only for the current prototype session. | Focused persistence and storage-failure regression; existing settings interactions. |

The final 2026-09-26 runs report **71/71 existing interactions passed** and **9/9 focused review regressions passed**, with no page-level JavaScript errors or external requests. The primary agent inspected the changes, corrected failures found during the focused run, rebuilt the prototype, and reran both suites against that build. Reports: [interactions.json](tests/interactions.json) and [review_regressions.json](tests/review_regressions.json). Both scripts exit with a nonzero code on failed checks.

Tests use Python with Playwright 1.63.0 and a fresh headless Chromium context. Set `CHROMIUM_PATH` to an installed Chromium/Chrome executable, then run `python tests/interactions.py` and `python tests/review_regressions.py` from this directory. The scripts serve the prototype on a temporary loopback HTTP port so localStorage can be exercised. They do not use an existing browser profile.
