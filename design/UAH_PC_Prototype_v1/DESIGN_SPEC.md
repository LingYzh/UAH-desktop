# UAH PC · 视觉与交互规格 v1

## 1. 设计基线

需求基线是仓库 `design/UAH_PC_HARNESS_FUNCTIONAL_DESIGN.md` 的完整功能范围。外观按本轮要求收敛到 Claude 网页端与桌面端：暖白主背景、浅暖灰侧栏、阅读优先的中央对话、低存在感工具记录、悬浮感克制的输入容器，以及可收放的工作面板。保留 UAH 名称和原有标志，不把独立产品包装成官方 Claude 客户端。

本原型不选定正式桌面技术栈。网页是交互载体，不构成 Electron、Tauri、WinUI 或其他方案的架构决定，也不改造现有 Android 应用。

## 2. 信息层级与布局

桌面布局是 `应用窗口栏 → 左侧导航 | 中央工作区 | 可选右侧面板`。窗口栏 35 px；中央页头 64 px；左栏默认 254 px，可在 220–340 px 调整；右栏默认 470 px，拖动时保留中央内容最小阅读空间。具体约束以 CSS 和运行中的原型为准。

左栏顶端固定新对话和搜索；快捷功能先显示 Agent、模型与账号、MCP、插件与技能，记忆、文件和设置在“更多功能”中展开。下方是按本地项目分组的会话和状态点；已完成、中止、失败、运行和等待审批不合并为一个状态。工作区头像固定在底部，收起左栏后也不随导航上移。

中央工作区不使用仪表盘卡片组织正常对话。用户消息使用浅暖灰气泡；助手正文无外框。工具摘要与正文共享内容列，不另套“完成 N 步”容器。新对话草稿与已开始的会话共用底部 composer 停靠位置，首次发送时输入区不跳位；新对话欢迎内容在上方独立滚动，长会话只滚动正文。

右栏是会话所属的工作区，不是全局管理中心。打开时作为第三栏挤占中央区域，不能悬浮覆盖对话。计划、后台任务、子代理、历史 Diff、浏览器和终端使用标签。面板种类、展开状态、固定状态和当前 Diff 随会话恢复。管理页面在中央独立展示，不挤入右侧窄面板。

窗口 ≤1100 px 时，右栏仍占据分栏空间，同时将左栏暂时压缩为图标栏。展开左栏会关闭右栏；关闭右栏后恢复原左栏宽度偏好。审批/错误状态和停止入口保持可达。更窄窗口优先收缩导航和辅助信息，不缩到正文无法阅读。1440×1000 是标准评审画布，另有 1366×768、1024×768、800×900、1920×1080 样本。

完整 Token 从实际 CSS 提取于 `design-tokens.json`。未允许按壁纸动态换色；主题有 light、dark、system 三种语义。状态颜色不能只靠红绿区分，Diff 同时有 +/- 与新旧行号，任务同时有状态文案。

界面采用系统无衬线字体，首页与少数阅读标题采用系统衬线回退，代码用等宽字体。不要从截图反推或分发品牌字体。中文和 Windows/macOS/Linux 字体度量存在差异，正式版以语义字号、行高和布局约束验收，不以截图某个字的像素宽度为数据模型。

正文主要使用 15–16 px，约 1.8 倍行高；工具与管理辅助文案约 12–13 px；代码约 11–12 px。宽代码局部横滚，也提供换行操作。首页欢迎标题使用约 26 px 的衬线标题，位于上方内容区，不能把这一字号应用到全部 Markdown H1。

## 4. 基础控件

按钮使用轻边框、约 8 px 圆角；主要行动用陶土色实心。危险操作保留红色文字与明确动词。默认禁用发送按钮，不以用户点击后的报错代替无效状态。

表单单选下拉统一使用 36 px 基准高度、8 px 圆角、右侧线性箭头和一致的 hover、焦点、禁用状态；紧凑筛选器只缩小尺寸，不更换视觉语言。浏览器支持可定制原生 select 时，选项弹层也使用同一主题的背景、圆角、间距和选中态；不支持时回退到系统原生选项列表，保留键盘和屏幕阅读器语义。

输入容器默认单行，输入换行时增高至约 180 px，之后在文本框内滚动；框内仅保留附件和发送 / 停止。目录与仓库分支在输入框上方，无 Git 分支时显示“没有仓库”；Agent、模型、权限、思考和上下文同处输入框下方。附件菜单包含本机文件、项目文件及其他本地会话的只读引用。紧凑上下文入口是单色圆环加占用百分比；容量未知时显示“容量未配置”，点击才展示分色分类详情。发送快捷键在设置中配置。

菜单相对触发器定位，接近窗口底部时向上展开。对话框将背景设置 inert，有 Esc 与焦点闭环。标题、关闭按钮和页尾确认区固定，长内容在内部滚动。普通反馈使用一份活动提示，持久错误还留在发生页面；实际产品应采用系统无障碍建议时长。

图标为 currentColor 的 24×24 SVG，线宽 1.65；图标与文字共用居中 flex，不按字体基线错位。独立 SVG 共 67 个，UAH 标志另存 64×64 viewBox。不要把品牌标志当作供应商协议图标。

## 5. 新对话、项目与并发

启动页是草稿，不生成空会话。目录可不选；只有输入为空时发送保持禁用。无目录会话可聊天，项目文件工具和 Shell 在绑定目录前不可用。首次有效发送后原子建立会话，随后导航或重复操作不得再次建立同一会话。附件属于当前草稿，新草稿不继承上一份正文和附件。

不设置独立的“会话默认值”页面。和移动端一样，在普通新草稿中调整的 Agent、模型、思考档位、权限模式和项目目录立即记为以后新草稿的选择；首次没有已记住模型时保持未选择并禁用发送。附加目录仅属于当前会话：从输入区上方的主目录选择菜单进入，选定主目录后即可添加，不要求先选模型；新会话和分支不继承。正文、附件与临时 worktree 也不继承。历史会话中的调整和从历史建立的分支不覆盖默认选择。发送快捷键留在外观设置中。

选到有运行中或等待审批会话的同一个 Git 主目录时，立即要求用户选择独立 worktree 或共享目录。普通目录只允许明确确认共享风险，不出现不能实现的 worktree。只有停止/完成历史的目录不提示。

Windows 目录权限分成工作目录、额外可读目录、额外可写目录、命令执行隔离四个概念，界面要展示**运行时实际生效**的范围和状态。全局设置页只管理项目目录；附加目录从当前会话输入区的主目录选择菜单进入，保存于该会话，切换或新建会话不得继承。主目录、附加目录和 MCP 本机工作目录都通过 Windows 系统文件夹对话框选取，不提供手填路径的主流程。Windows 客户端取得绝对路径后要进行规范化、可访问性和重解析点校验；网页原型使用浏览器的文件夹选择器，只能可靠展示名称，不得把名称冒充绝对路径。UAH 自有文件工具分别校验读写路径；Shell 必须由独立 Windows 沙盒约束，不能用文件工具目录列表冒充命令沙盒。隔离尚未接入或失效时显示未验证/未隔离，并限制无审批的命令执行。使用真实路径做规范化与重解析点校验；盘符大小写、符号链接/联接点、UNC/网络共享和工作目录迁移都要验证，不能只做字符串前缀比较。Windows 桌面实现可用 [IFileDialog 的 FOS_PICKFOLDERS](https://learn.microsoft.com/en-us/windows/win32/shell/common-file-dialog)；网页原型使用 [showDirectoryPicker](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。

Codex 官方运行时使用其 Windows 原生沙盒、额外可读目录与 workspace-write 可写根目录；UAH 发出请求后仍要回读其有效权限，不能仅凭本地表单判断成功。Claude Code 原生 Windows 目前没有其 Shell 沙盒；附加工作目录按 Claude Code 自身的权限模式提供文件访问，不能标成“只读硬隔离”。WSL2 沙盒属于单独运行环境，未来接入时单独显示。其他官方运行时若未报告目录能力，保持“未验证”，不提供虚构的统一沙盒承诺。参考 [Codex Windows 沙盒](https://learn.chatgpt.com/docs/windows/windows-sandbox)、[Codex 权限与可写根目录](https://learn.chatgpt.com/docs/sandboxing)、[Claude Code 工作目录与规则](https://code.claude.com/docs/en/permissions)、[Claude Code 沙盒平台支持](https://code.claude.com/docs/en/sandboxing)。

工作区切换不能中止任务；模拟流式输出支持在后台继续，停止会取消后续字符生成。真实实现还须把取消贯穿网络、工具、子任务和屏幕控制。退出时记录中止原因，重启不自动恢复执行。

## 6. 对话与工具

命令完成的收起文字严格是“运行了命令”。运行、等待审批、失败和中止不能也显示成完成。展开后使用同一个调用保存的 command 与 output，纯文本渲染、可复制，不提供以查看历史为名的自动重跑。

编辑收起为“已编辑 文件名 +增行 −删行”。原地展开历史 Diff，不打开阻断式工具弹窗。用户可以明确点击“在右栏查看”获得更宽视图；这不是默认跳转行为。正式状态键必须包含 conversation / round(or message) / toolCall；原型 fixture 使用独立场景调用 ID，不能照搬简化的样本键。

每轮均有文件改动区，没有文件改动也显示“本轮无文件改动”。来源区分文件工具、Shell、子代理汇入父任务、以及归属不确定。并发编辑不能因为 watcher 看见了变化就归因给某个工具。

编辑消息只修改可见历史，不重新发送或重新执行工具。删除消息不撤销文件。重新生成只作用于适用的最新轮次；正式实现要区分运行时可再生与不可再生记录。原型的回复编辑器为固定样本文本，不是完整 Markdown 编辑器。

## 7. 历史 Diff

右侧是保存的历史快照，明确展示轮次、路径、来源、时间和增删统计。文本 Diff 有上下文、新旧行号、+/-、低饱和红绿底，宽行局部滚动。精确统计须来自同一份已保存快照；示例行数已与展示样本对齐。

“打开当前文件”和“历史 Diff”是分开的操作。切到当前文件后再回到对话，不可把磁盘最新内容写回旧快照。

二进制、大文件超预算、快照缺失、纯重命名和来源不确定均有专用状态。缺少证据时不显示伪精确统计。原型的文件、时间、哈希、大小均为样本，不能用于仓库验收结论。

## 8. 计划、后台与子代理

计划栏只展示当前会话实际保存的计划文件；尚未产出文件时显示“还没有计划”。运行时的临时计划事件和聊天文字可以留在对话中，但不能被右栏冒充为计划文件。查看文件不会批准执行；执行批准仍在主会话明确入口。计划模式只可使用受限的计划文件写入能力，不授权业务代码修改或桌面动作。

后台任务栏只展示当前会话创建的所有任务，包括进行中和已结束的记录；可按运行、审批、完成、失败、中止筛选，展开详情并停止运行中的任务。切到等待审批会话后要直接找到主对话审批区。

子代理栏有两级：先列出当前会话生成的全部子代理，再点击一个子代理只读查看完整会话记录，返回后仍是列表。UAH 的子代理仅单层委派；需要授权时回父会话，不通过打开子会话提高权限。官方运行时可能有不同结构，必须按真实返回的层级展示并标记来源；原型不宣称对这些运行时做过验证。

## 9. 模型、供应商与运行时

自配 API 和订阅运行时共享模型选择 UI，但不能共享虚构的执行语义。API 侧有协议、地址、Key、模型目录、手动 ID、能力覆盖、高级模板与测试入口；新供应商默认禁用。模型能力子编辑先返回供应商草稿，由供应商保存统一提交。

官方运行时使用安装检测、官方登录、当前一个账号、模型查询和能力信息。没有上报的额度或上下文保持未知，不显示成 0。思考档位未上报时，可按已知协议提供临时选项并在问号说明中标明来源与可能被上游拒绝；明确声明不支持时不提供滑块。登录不接收密码、复制 token 或把订阅凭据变成 API Key。

每个官方运行时有独立适配页，明确映射只读、计划、需审批、自动模式。UAH 请求的权限与官方有效权限不一致时，输入区应显示差异并阻止静默放权；只有官方通道能回传审批决策时才提供批准按钮。计划事件、工具、文件变更和子代理消息按真实事件类型呈现，未知类型保留原名与状态。Antigravity headless 无交互审批通道时，“需审批”必须不可用。

跨运行时选择先确认迁移范围，然后建立分支草稿。可见对话、可保存结果摘要和已选择附件引用可以进入适配过程；隐藏推理、私有缓存、内部任务状态和待处理审批不原地继承。分支首次发送前仍检查目录并发。

思考入口仅显示 `Medium`、`High`、`XHigh` 等大驼峰英文档位名。弹出的紧凑卡片只保留当前档位、模型名、滑块和两端速度提示；说明收进右上角规整的问号图标，悬停或键盘聚焦时出现。没有重置按钮或档位详情列表。已填充部分隐藏档位点，拖动跨档设置轻微滞后与停靠；Ultra 使用紫色流动填充，并遵守减少动效设置。明确声明的档位优先；未上报时按协议提供临时默认档位，允许上游返回不支持错误；自定义模板没有统一思考字段，须在模板中显式定义。Ultra 是官方运行时的复合模式：Claude Code 的 `ultracode` 为 xhigh 推理加动态工作流；Codex Ultra 为当前模型最高推理档位加主动子代理编排。UAH 分别核对模型档位、工作流能力和实际子代理状态，不能把 `ultra` 字面值发给普通模型 API，也不能给未确认支持的运行时开放。上下文的本地分类、容量比例和服务端上一轮用量是不同信息源；缓存不能重复相加。压缩只影响后续上下文，保留原始历史。

运行时依据：[Claude Code 模型配置](https://code.claude.com/docs/en/model-config)、[Codex 模型能力表](https://github.com/openai/codex/blob/main/codex-rs/models-manager/models.json)。这里展示的是原型能力样本；正式接入时仍需读取当前运行时的有效模型、强度上限及工作流状态。

## 10. MCP、插件与 Skills

MCP 支持本机 stdio 与远程 Streamable HTTP 的完整配置界面。本机填写可执行文件、逐项参数、环境变量与超时，工作目录通过文件夹选择器选取或留空跟随项目；远端填写 URL、认证方式、OAuth scopes 或 Token / 请求头、超时。另选工具、资源、提示词能力、默认审批策略和项目启用范围。详情页展示配置摘要并进入完整编辑；发现的工具、资源、提示词、调用记录分开。服务器认证、连接失败、可用状态留在所属页面。全局添加与项目启用是独立层次，还要与 Agent、会话权限求交集。原型不保存凭据值。

插件导入先展示来源、格式、版本与清单。Skills、Agents、MCP、规则、hooks 分别识别，不在安装或启用时执行脚本。每个 executable hook 要单独展示命令、目录、来源与授权。更新先预览冲突并备份；卸载保留可恢复状态；恢复不会自动恢复执行授权。

Skills 页面按来源列出技能，正文和关联资源可阅读。没有捏造远程市场，也不把读取 Skill 视为获得执行权限。官方运行时兼容性仍由适配层逐项验证，不静默改写官方全局配置。

## 11. 电脑控制与浏览器

电脑控制和 Agent 浏览器操作默认关闭。权限依次经过总开关、Agent 工具、会话模式、目标授权、屏幕租约与有效观察。只读/计划禁止写入；需审批模式的动作逐次确认；Auto 仅在已授权范围内生效。

同一时刻一个父会话持有屏幕租约，子代理共享父租约而不是抢占。窗口、页面或目标变化后旧观察失效，重新观察之后才可提交动作。停止和退出必须取消后续动作并释放租约。正式控制优先 UI Automation，坐标动作使用已验证观察；网页只展示相关决策与安全状态。

浏览器有多个标签、地址、前后退、刷新、手动登录与操作日志。使用独立配置文件，Cookie 不提供给模型 API、搜索服务或其他网站。原型页面是离线样本，不嵌入外部网站、不收集密码、不截取用户真实屏幕。

## 12. 终端、文件、记忆、迁移

手动终端可以创建多个示例标签，各自保存输出；模型命令放在独立只读记录标签。示例终端仅识别 help、pwd、dir、git status、npm test、clear，不执行任意命令。真实 PTY 必须由桌面后台提供，并区分用户与模型发起来源。

文件页是当前工作区视图，支持源码/预览切换和添加至对话。记忆分全局和项目范围，保存原文，不用后台模型悄悄重写。

数据交换先验证、预览冲突，逐项选择更新、副本或跳过，再确认导入。导入会话保持中止，Android 设备控制授权不转成 Windows 授权。正式 API secrets 使用 Windows 安全存储；原型只演示边界，不宣称实现安全存储。

JSON 导出可实际生成原型数据，默认排除密钥、附加请求头与执行授权；敏感选项另需确认，原型没有真实密钥可导出。正式 Android/UAH 备份格式、插件归档解包、真实文件恢复必须另做集成验收。

## 13. 实施原则

截图、Token、状态矩阵共同构成 UI 基线。不要根据一个首页截图自行发挥剩余模块，也不要把 fixture、原型导览、示例错误和任意脚本执行器接进正式产品。原型不是业务数据模型；状态转移与权限必须继续以项目实际 Domain / runtime 设计为准。

文案在交接时分层处理：可保留的用户操作文本、由真实状态驱动的权限/错误说明、必须移除的设计与演示说明，详见 [COPY_GUIDE.md](COPY_GUIDE.md)。源码使用 `prototype/remove`、`fixture/replace`、`mixed/split` 标记，并在构建时更新 `COPY_INVENTORY.md` / `.json`；正式实现按清单逐项删除、替换或拆分，不能批量删除真实权限文案。
